# Pet Transformer

A transformer language model written from scratch in C++20, built to learn
modern C++ and how LLMs work underneath. It is a learning project and a work in
progress.

**Roadmap:** tokenizers (done) → dataset encoding → transformer model → CUDA
kernels for the layers.

## Tokenizers

All three are trained and run without external libraries. The algorithms follow
chapter 6 of the [Hugging Face LLM course](https://huggingface.co/learn/llm-course/chapter6/1).

| Tokenizer | Based on | Notes |
| --- | --- | --- |
| WordPiece | [HF course 6.6](https://huggingface.co/learn/llm-course/chapter6/6) | ASCII text. |
| BPE, byte-level | [HF course 6.5](https://huggingface.co/learn/llm-course/chapter6/5), GPT-2 | 256-symbol byte alphabet, so any valid UTF-8 text can be encoded. Text is NFC-normalized first. |
| Unigram | [HF course 6.7](https://huggingface.co/learn/llm-course/chapter6/7) | SentencePiece-style, on Unicode code points. Prunes by loss without EM re-estimation, as the course does. |

Unicode support is also from scratch: UTF-8 decoding/encoding and NFC
normalization. The normalization tables in `src/private/unicode_norm_tables.hpp`
are generated by `tools/gen_unicode_tables.py` from the
[Unicode 18.0.0 UCD XML](https://www.unicode.org/Public/18.0.0/ucdxml/).

### Results

[TinyStories V2](https://huggingface.co/datasets/roneneldan/TinyStories),
vocabulary size 4096, minimum word frequency 10, measured on the full
validation file (157,832 lines):

| | BPE (byte-level) | WordPiece |
| --- | --- | --- |
| Tokens per word | 1.026 | 2.53 |
| Vocabulary used at least once | 94.0% | 40% |
| `decode(encode(s)) == s` on every line | yes | yes (ASCII lines) |

Unigram has not been measured on TinyStories yet.

## Build

Requires CMake 3.28+ and a C++20 compiler. Tested with clang++ on Windows.
[doctest](https://github.com/doctest/doctest) is fetched by CMake.

```sh
cmake -S . -B build -G Ninja -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
```

clang-tidy runs on every file when it is found, which slows the build. Add
`-DENABLE_CLANG_TIDY=OFF` to skip it. Executables are written to `bin/`.

## Usage

Run from the project root (data paths are relative to it):

```sh
bin/PetTransformer [wp | bpe | uni] (--train | -t) | (--validate | -v)
```

`wp` (WordPiece) is the default. `--train` writes `<tokenizer>_vocab.txt`, and
`--validate` loads it and reports the statistics above.

By default (`DEBUG = 1` in `src/main.cpp`) training and validation use the toy
corpus in `data/testfile.txt`. For TinyStories, set `DEBUG` to `0` and download the data:

```sh
hf download roneneldan/TinyStories TinyStoriesV2-GPT4-train.txt TinyStoriesV2-GPT4-valid.txt --repo-type dataset --local-dir data
```

## Tests

One doctest suite per component (`tests/`). Besides fixed examples, the
tokenizer tests check properties on random input (round trip, deterministic
training) and compare against slow reference implementations.
